# M3 设计:扫描回写(scan / import)

> 承 [kickoff.md](../kickoff.md) §9 与实施计划 §9 的 M3。下发(distribute)的逆向:把 agent/目录里已有的
> rules/mcp/skills 收进库房统一治理。安全红线见 [AGENTS.md](../../AGENTS.md) 不变量 6。

## 1. 流程(`engine/scan.ts`)

```
读目标(adapter paths + mcp codec.decode) → 规范化 canonical → 脱敏(密钥→占位符)
  → --select 过滤 → 冲突裁决 → 写前明文护栏 → 写库房(applyScan)/ 仅清单(scanPlan)
```

- `scanPlan` 只读产出候选清单(plan/apply 分离,不变量 3);`applyScan` 才写库房。
- 候选内部携带写库房载荷(`ScanCandidate.payload`:rules 文本 / 脱敏后的 canonical server / skill 源目录),
  对外 `ScanItem` 只暴露 kind/name/status/action/secretRefs/source —— **真值/大对象不进 JSON 输出**。

## 2. 不吸收自身下发物(provenance)

避免把 cellarer 自己写的内容当用户新增重复收编:

- **rules**:`markers.isGenerated`(首行 `<!-- Generated by cellarer -->`)→ 跳过。
- **skills**:跳过软链条目(cellarer 下发的 skill 多为软链指向库房真源 / 共享池),只收真实目录。
- **mcp**:靠库房同名制品判 `new` / `conflict`。

> **M4 待补**:kickoff §9.2 要「台账 + 指纹双保险」。当前 mcp/skills 无台账校验,空库房或改名场景仍可能
> 把自身下发物当 `new` 重吸收。M4 接 `loadLedger` 过滤「target 命中台账且 generated」的项。

## 3. 密钥脱敏(安全红线,kickoff §9.2)

**两道防线**,确保真值绝不进库房:

1. **结构化脱敏**(`redactServerSecrets` + `redactFields`):mcp 的 `env` / `headers`(map)、`args`(数组)、
   `url`(整值)逐字段过 detector,命中 → 换 `${CELLARER_SECRET:<derivedName>}`,真值丢弃,引用名记入 `secretRefs`。
2. **写前明文护栏**(`guardPlaintext` + `plaintextInStorePayload`):把候选序列化为「即将落库的文本」,
   跑 `scanTextForSecrets` 高置信扫描。结构化脱敏覆盖不到的(rules 自由文本里的 token、custom-kind server
   内嵌密钥)→ **拒绝该项入库**(转 skip + 告警),绝不把明文写进库房。

> 召回边界:写前护栏只认厂商格式(`ghp_`/`AKIA`/JWT/PEM…)。低熵 / 非厂商格式密钥(如 `DB_DSN` 内嵌口令、
> 短人选口令)结构化脱敏与文本护栏都可能漏 —— 这是检测的固有限制,M4 评估是否对 mcp 全字段做名启发式兜底。

真值入库后,CLI 提示用 `cellarer secret add <name> <value>` 存入 vault(真值只进加密 vault)。

## 4. 冲突策略

库房已有同名制品时(kickoff §9.1):

- `keep-theirs`(默认):扫描来的覆盖库房(「收编」)。
- `keep-mine`:保留库房,跳过扫描项。
- `copy`:新建副本(`<name>-<agent>` 后缀;仍冲突加序号)。

副本命名既避开库房既有名,也避开**本轮已占用名**(防两个候选裁决到同一副本路径互相覆盖)。

## 5. 安全:制品名

`assertSafeName` 只允许 `[A-Za-z0-9._-]`(拒 `.`/`..`/含分隔符),防扫描来的恶意 server/skill 名带 `../`
把写入穿越到库房外。写时校验(applyScan 落地处)。

## 6. 通道标签(`--into-channel`)

`tagArtifactChannels`:给本次导入的制品追加 `[artifacts."<kind>/<name>"]` 通道标签。
smol-toml stringify 丢注释(见计划 §6),故**追加**缺失块而非整体重写,保留用户既有内容与注释;
已有该制品标签的跳过;写前 `parseConfig` 自校验合法性。

## 7. 非交互(CI 友好)

scan 默认即非交互(无确认提示):`--dry-run` 预览、`--select <names>` 缩范围、`--json`(或 `CELLARER_JSON=1`)
出结构化结果、`--conflict` 定策略。无需 `--yes`/`--all`(无 prompt 可跳过)。

## 8. 遗留到 M4(评审记下)

- ledger-based provenance 双保险(§2)。
- applyScan 消费预计算的 scanPlan(消除重复 I/O 与 plan→apply TOCTOU 窗口)。
- redactFields 对低熵/非厂商格式密钥的召回(§3 召回边界)。
- skill 目录内文件的明文护栏(当前只扫 rules/mcp 文本)。
- skill 拷贝入库的原子性(linkOrCopy clearDest→cp 非原子)。
